# Frontend guidance

This area inherits `../AGENTS.md`.

- Build a locally bundled Svelte UI. Keep `vite.config.js` output in `../.local/build/frontend`, relative asset URLs, no inline assets, and no production source maps unless a reviewed requirement changes them.
- There are two pages: `index.html` (`src/main.ts`, the main window) and `call.html` (`src/call.ts`, the call window of ADR-0060). The call window may call only the commands in `src-tauri/capabilities/call.json`; do not use other bridge calls in `CallWindow.svelte`. That includes `call_devices` and `set_call_devices` (ADR-0065) for `CallWindowDevices.svelte`, but no device tests. Its load and save order (saves one at a time, none dropped, the newest sets the result) is in `src/callDevicePanel.ts`, which takes the bridge calls as arguments. The choice of the large video is pure logic in `src/callView.ts`: a pick of the viewer wins, a shared screen is large only when nothing is picked, and a feed that goes away drops its pick. Scale pictures with CSS only; never ask the core for a larger one.
- Video effects (ADR-0068): `CallVideoEffects.svelte` holds the controls (background, blur strength, colour filter, mirror) for both `CallDevices.svelte` and `CallWindowDevices.svelte`; the texts, menus and value checks are in `src/calls.ts` (`backgroundOptions`, `blurValue`, `plainEffect`). Offer blur and the pictures only when `CallDevices.backgroundEffects` is true. The call window's effect saves go through `DevicePanel.saveEffect`, in the same queue as its device saves. The mirror is CSS only (`tileLayout`, own tile), from `CallStatus.mirror` in a call and from the device record in the camera test; the others always see the picture as it is.
- The technical details (ADR-0066) are `CallStats.svelte` (the panel, opened by one icon button in `CallWindow.svelte`) and the pure `src/callStats.ts` (contract check, units, table rows). The panel turns the readings on when it mounts and off when it is destroyed, through `startCallStats` and `stopCallStats` in the bridge, which send them one at a time in the order asked. After each reading, handled or dropped, the bridge calls `call_stats_read` with the page count, so the host sends the next (it holds one in flight per page). The bridge drops a reading that `parseCallStats` refuses. Show every number with its unit from the reading only, and show user IDs and device IDs as escaped text. A table's caption is `CallStatsCaption.svelte`, which puts the user ID and the device ID each in its own `<bdi>`. The details and the device panel are open one at a time (`openDevices`, `openStats`). The call window closes the details when the call ends or a call in another room replaces it (`statsStayOpen` in `callWindow.ts`); keep that rule, because the panel starts its readings only when it mounts.
- Put all Tauri API access in `src/bridge/index.ts` or another module under `src/bridge/`. Components use the typed bridge. Do not call `invoke`, Tauri globals, or host APIs directly from components.
- Import public DTOs from `../crates/contracts/generated/contracts.ts`. Change Rust definitions and run the exporter when the DTO contract changes. TypeScript types do not validate runtime input or authorize commands.
- Render names and message bodies as escaped text. Preserve bidirectional isolation in `src/Message.svelte`, `src/RoomList.svelte`, and `src/Timeline.svelte`. Do not use `{@html}`, HTML insertion APIs, automatic previews, or arbitrary remote images.
- Keep timeline state bounded. Preserve event-ID deduplication, visible gaps, subscription cleanup, serialized subscribe/unsubscribe operations, and rejection of stale results when the selected room changes.
- Subscribe before the initial fetch. Treat change notifications as invalidations, then fetch bounded pages through the bridge. Do not put message content in notification queues.
- Keep loading and error states usable. Use semantic controls, keyboard access, and accessible labels. Report native accessibility checks separately from Node rendering tests.
- Run `python tools/dev.py frontend` from the root. It runs `svelte-check`, Vite build, and Node tests. The build must precede tests because `tests/build.test.mjs` inspects its output.
- The tests write the line coverage of `src/**/*.ts` to `../.local/coverage/frontend/lcov.info` (`npm run coverage`), which SonarQube reads. Node's coverage sees only modules Node loads itself, so tests import TypeScript modules directly (`../src/x.ts`); load only Svelte components through Vite. Keep `src` TypeScript erasable (`erasableSyntaxOnly`: no parameter properties or enums) and give relative runtime imports their `.ts` extension.
- Run `python tools/dev.py contracts` for public DTO changes. Check `src-tauri` permissions and core protocol changes when adding a bridge operation.
- Keep exact dependencies and `package-lock.json` aligned. Use `python tools/dev.py bootstrap` for locked installation; do not use commands that download an unpinned compiler.
- Join refusal (ADR-0063): `NOT_PERMITTED_TEXT` in `src/calls.ts` is the one text for a blocked or refused join, from readiness (`not_permitted`, the header's call buttons) and from the join error (a ring's answer button). The core checks the permission; the page never decides it. The call end `alone` has its text in `END_TEXT`. Room settings, Permissions lists the level `join_calls` as "Join calls" in the "Calls" group.
