Matrix desktop client · Rust · GPL-3.0

A Matrix client designed to withstand targeted attacks.

Persephone is a Matrix chat client for Windows, Linux and macOS, written in Rust. It's made for everyone, but engineered to the standard a targeted person needs: security that holds up against attacks aimed at you, not just everyday threats. Every message, name, link and image is treated as hostile, even after it's decrypted.

Not ready for use. Persephone is in early development: feasibility work (P0) continues alongside the first application milestones. There is no application to download, and none of its security controls are production-ready. Do not use any part of it for real conversations.

What the first release is meant to do

  • One account

    Sign-in to a single Matrix account. Login methods are still being decided.

  • Rooms and history

    Room list and message history, using Sliding Sync with a classic sync fallback.

  • Text and images

    Sending and receiving text and images, with stricter media handling.

  • Encrypted chats

    End-to-end encrypted rooms. Verification and recovery behaviour is still being specified.

Interoperability with the Merovingian homeserver is a primary acceptance criterion; Synapse and other standard Matrix servers are also targets.

Security approach

The design assumes a capable adversary who may target one user directly. These are design decisions, not finished features.

All content is untrusted

Message text, display names, links, avatars and attachments are hostile input, before and after decryption. The interface is designed to render them as inert text: no HTML, scripts or automatic link previews.

Cryptography stays in the SDK

Matrix encryption is handled by the maintained Matrix Rust SDK with explicitly selected features, never reimplemented by the client and never moved into the web view. ADR-0002

Images decode in a sandbox with no network

Image decoders run as WebAssembly, planned to sit inside a separately contained process. The module can call only three host functions for its input and output, so it cannot reach sockets, files, clocks or other processes, whatever the operating system allows. ADR-0003

TLS 1.3 only

Every connection will require TLS 1.3. Older protocol versions will be refused.

Rust owns the logic

The web view is only the interface. Sessions, keys, storage and Matrix traffic are planned to live in the Rust core, behind a narrow, validated command boundary.

Defence in depth

No single bug should be enough. Hostile content has to get past several independent layers before it could reach keys, the network or the rest of the system.

Planned architecture

Three trust zones. Arrows are the only paths data takes.
