# Contained worker broker

This is trusted code for launching and supervising a hostile-media worker. Follow ADR-0003 and the worker frame protocol.

- Start the Windows worker suspended. Apply the AppContainer, process mitigations, inherited-handle allowlist, and Job limits before it runs.
- On Linux and macOS, start the worker with an empty environment, `/` as its directory, only descriptors 0 to 2, a new session, and rlimits. Send no input until the worker's `WorkerReady` frame arrived and the OS check passed (`/proc/<pid>/status` on Linux, `sandbox_check` on macOS). Kill the worker on any mismatch.
- The call worker (`start_call_worker`, ADR-0049) lives long and has no deadline. On Linux it gets the call rlimits (4 GiB address space, files of at most 256 MiB, no core dumps, 256 descriptors; no CPU or process limit). The file limit is not 0: libpulse sizes its memfd pool with `ftruncate`, and a limit of 0 kills the worker with `SIGXFSZ`. The limit is per file, so keep the worker without a writable path (its `/dev/shm` rule is read only): only memfds can grow, and they go away with the worker. It also gets the environment `XDG_RUNTIME_DIR`, `HOME` (absolute only), `LANG=C` and, for a chosen sound server device (`CallSound`), `PULSE_SOURCE` or `PULSE_SINK`. A device name outside the name rule (1 to 128 bytes of ASCII letters, digits, `.`, `-`, `_`, `:`) refuses the launch; never clean it up. It also gets one `--camera=` argument and descriptor 3 as the camera channel. On macOS it gets the same limits without the address-space bound, with no file writes, and an empty environment. The caller must call `confirm_contained()` after the worker's `Ready` and before it sends input.
- The Windows screen helper (`start_screen_helper`, ADR-0067) is the one launch here that is not an AppContainer: Windows.Graphics.Capture is refused there. Keep every other control: start it suspended, in a Job (one active process, kill on close, 512 MiB, UI limits), put it in the Job before it runs, give it the call worker's mitigations except dynamic-code prohibition and Win32k lockdown (WGC and Direct3D need both; say so in each change), block child processes with the policy and the Job, start it with `DETACHED_PROCESS` (a console would need `conhost.exe`, a child, and fails with `0xC0000142`), inherit only the two pipe handles of `ScreenHelperPipes` through `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` (`helper_inherit_list`), pass null standard handles and the minimal environment, and accept only the argument characters of `helper_argument_ok`. `LongLivedWorker::give_handle` duplicates a pipe into the call worker; the caller closes its own copy. The two tests that start the test program as a probe (`helper_probe_child`, `helper_probe_sleep`, both `#[ignore]` and run only through those tests) show the launch works under all of this. Never add an argument that holds a secret or untrusted text.
- Preserve minimal environment forwarding. Never pass account credentials, store paths, keys, or unrelated handles to the worker.
- Enforce the wall deadline outside the decoder. Ensure every success and error path terminates the worker and releases owned handles and profiles.
- Validate one bounded reply and its exit status. Preserve distinctions between containment failure, decode rejection, protocol failure, deadline expiry, and abnormal exit.
- Keep resource reservations attached to returned pixels while they remain live.
- AppContainer alone does not establish sender-side network denial. Keep WebAssembly isolation as the decoder capability boundary, and retain the documented OS residual risk.
- Do not silently launch an unrestricted worker on platforms without implemented containment.

## Checks

- Use `python tools/dev.py rust` to build the guest, build the workspace worker binary, and run broker integration tests in the required order.
- For a focused Windows run, first build the guest with `cargo build --locked --release -p persephone-media-decoder --target wasm32-unknown-unknown`, then build `cargo build --locked -p persephone-media-worker`, then run `cargo test --locked -p persephone-media-broker`.
- `tests/contained_worker.rs` runs on Windows, Linux and macOS and launches the real contained worker. A package-only test run does not build that worker automatically.
- macOS code (`src/macos.rs`) cannot be compiled on the Windows development machine. Only CI builds and tests it.
- Benchmarks are ignored by default. Follow `tests/benchmark.rs` for the release build and `PERSEPHONE_BENCH_DIR` setup; do not report an ignored benchmark as executed.
