# Call worker

The contained process that runs one call (ADR-0043). It joins one LiveKit room with frame encryption and platform audio. It speaks the bounded protocol of `crates/call-protocol` over stdin and stdout.

- Treat the core's messages and the SFU as untrusted. Validate every identity before it goes back to the core. Send no free text, only closed `FailureCode` values. The one exception is `FromWorker::Diagnostic` (ADR-0058): `diagnostics.rs` sends `log` records and room event notes only while the core has sent `SetDiagnostics { on: true }`, at most 256 waiting, 200 a second and 8 per writer round after control messages and a waiting picture. `log` records take at most 192 waiting and 150 a second (`Source::Library`), so a libwebrtc flood never drops the room event notes (`Source::Note`). Never put a token, JWT, key or frame key in a note.
- Stdout is the frame channel. Write nothing else to it. Write nothing to stderr. Add no logging output other than the diagnostic records above.
- Keep the JWT, TURN credentials and frame keys in `Zeroizing` until they go to LiveKit. Move them out with `std::mem::take`; do not copy them. Never log them.
- Use bounded queues only. The LiveKit event receiver is unbounded inside the SDK; the worker drains it in one task.
- Check containment before reading any input. On a missing control send `Ready`, then `Failed(Containment)`, and exit. The feature `dev-uncontained` skips the exit for local tests only. Never enable it in a build that ships.
- A decryption failure of one remote participant does not end the call.
- Keep each LiveKit type inside `session.rs`. Keep `mapping.rs` and `video.rs` free of I/O and LiveKit types so they stay unit-testable.
- Camera and video (ADR-0048): `camera/mod.rs` is the platform-neutral API (`list`, `open`, `Capture`, `CapturedFrame`) with no OS or LiveKit types. New OS backends go in `camera/<os>.rs` behind the same API. Each one needs its own ADR and containment review. Do not add one without them.
- Windows camera: the open needs the `webcam` device capability SID that the broker adds (`CALL_DEVICE_CAPABILITIES`); without it `ActivateObject` fails with `E_ACCESSDENIED` (`docs/evidence/camera-windows.md`). `camera/windows.rs` notes each failed step and its HRESULT through `log` (`note`, `failed`, `missing`), never a device ID or name. Run the ignored camera test in `crates/core/src/platform/windows/call.rs` after a containment change.
- Screen sharing (ADR-0053, ADR-0064): `screen/mod.rs` is the platform-neutral API (`open`, `Capture`, `CapturedFrame`, `Ended`, `Grant`) with no OS or LiveKit types. Backends: `screen/linux.rs` (PipeWire over the ScreenCast portal remote of kind `s`, shared-memory buffers only, BGRx, RGBx, BGRA and RGBA); `screen/windows.rs` with `screen/frame_pipe.rs` (no capture of its own, ADR-0067 proposed: it reads the frames that the screen helper writes to a pipe, see below); and `screen/macos.rs` (ScreenCaptureKit through `objc2`, ADR-0064; one display, BGRA, at most 1920x1080 and 5 frames per second, no window left out; its pure rules are in `screen/display.rs` and run on every OS). Windows.Graphics.Capture and DXGI duplication fail with `E_ACCESSDENIED` in the call AppContainer (`docs/evidence/screen-share-windows.md`), so the worker does not capture the screen on Windows: `crates/screen-helper` does, outside the container, and its code (`wgc.rs`, `monitor.rs`) is not part of this crate any more. The GDI capture moved to the containment gate (`tests/platform/windows/src/gdi.rs`), which still measures what the container can do. Give the worker no capability and no relaxed mitigation for screen sharing, and remove no Win32k lockdown gap by accident: the worker still has no Win32k lockdown (its audio stack needs it), so it can still copy any monitor with GDI; ADR-0067 says so. On Windows the core names the monitor with `ScreenTarget::Monitor` (GDI device name, size in pixels and rectangle, call protocol version 12) and starts the helper for it; the worker only checks that frames arrive. `ToWorker::ScreenFrames { share, handle }` (before `SetScreen`) names the read end of the helper's frame pipe as a handle value inside the worker; `session.rs` keeps at most one (`screen_frames`), adopts it only when it is a pipe end (`GetFileType` and `GetNamedPipeInfo`, which refuses a socket) and none of the worker's standard handles (`frame_pipe::adopt`), never closes a handle that is not a pipe, and gives it to the start of that share only (`screen_grant`); another share's pipe stays for its own start or is dropped by the next `ScreenFrames`. `frame_pipe::PipeReader` reads with `PeekNamedPipe` and short waits (never a blocking read), so a stop or a stalled helper (`STALL_TIMEOUT`, 3 s inside an item) cannot hold the capture thread. `screen/windows.rs` waits for the first item (at most 8 s): a picture opens the share (`On`), an end item gives `NotFound` or `Unavailable`, and silence or a bad item is `Unavailable`. Later, `persephone_call_protocol::screen_frame::read_item` checks the share, format, size, stride and length of each item before it allocates; an end item ends the share (`Ended::Source`, `NotFound` or `Failed`), and a pipe that closes with no end item, or any bad item, is `Failed`. Pictures are 5 a second at most from the helper, and the session's own limiter still applies. On macOS the core names the display with `ScreenTarget::Display` (CoreGraphics display ID and size in points, version 12) and asks for the Screen Recording permission; the worker never asks, takes only the `SCDisplay` with that ID, and a different size or a missing ID is `NotFound`. `setCaptureMicrophone` exists from macOS 15 only: keep it behind `available!(macos = 15.0)`. Its Seatbelt additions are "to be measured on a Mac", and the backend was not compiled with the full worker or run on a Mac. Other targets use `screen/unsupported.rs` and report `Unavailable`. The Windows `windows` dependency keeps no graphics, Direct3D, DXGI, GDI, WinRT capture or DPI feature; add none back. The core names the screen (`ScreenTarget`); the worker never lists screens to the user and never takes another. The worker publishes one VP8 layer (`TrackSource::Screenshare`, screencast source, at most 1920x1080, 5 frames per second, 1.5 Mbit/s, no simulcast) and decodes at most one remote screen share on tile 5 at 1280x720 and 5 per second; more wait, and each member that shares shows as `ScreenSharer`. A screen start and stop reuse `CameraGate` (one open at a time, stale results dropped), and the own screen track gets the own key index before the first frame like the camera. There is no own screen preview.
- Other SFUs (ADR-0054): `Subscribe { index 1..=3, url, jwt }` opens one more `Room` as subscriber only. The connect runs on its own task (never awaited in the event loop) and its result returns through a bounded channel (`Connected`); `OtherEvents` is the one place that drains the rooms' event receivers, fairly, inside the single event loop. A secondary room never calls `publish_track`, never sets an own key index and never changes mute, camera or screen state; those use the main room only. Every participant, speaker, video and screen-share message carries the connection index (0 is the own SFU), and a remote video track is keyed by identity, track and connection. All rooms share one key provider (`RemoveParticipant` and `SetKey` go by identity). A secondary connect failure, a `Disconnected` event or a closed event queue sends `Connection { up: false }` and never ends the call; `mapping::Slots` uses each index once and never reopens it. `Leave`, `Eof` and every failure close every secondary room and stop connects that are still running (`close_others`). Do not log the URL or the JWT.
- Containment (ADR-0049): `containment/mod.rs` holds the bit constants and `missing_controls()`; one module per OS (`windows.rs`, `linux.rs`, `macos.rs`). Never change a released bit value. macOS (`containment/macos.rs`) applies the call Seatbelt profile with `sandbox_init` before any input and checks it; its service list is "to be measured on a Mac" and was not compiled or run on the development machine. Linux (`containment/linux.rs`) applies stage 1 before any input (non-dumpable, Landlock ABI 3 or newer, seccomp deny list; `clone3` returns `ENOSYS`) and `containment::apply_stage2()` after the audio connection and before `Room::connect` (no new `AF_UNIX` socket, no Landlock calls); a stage 2 failure ends the call with `Containment`. Keep the Landlock path table to the ADR; add no path without an ADR change. No path is writable without V4L2; `/dev/shm` is read only, because the file limit (256 MiB) is per file and a file there would outlive the worker.
- Windows default devices (ADR-0043 amendment of 2026-11-24): with no choice, `select_devices` opens the console default endpoints that `sound_defaults.rs` reads through MMDevice, when libwebrtc lists them (`mapping::system_default`). Never let it replace a chosen device: a missing choice stays `DeviceNotFound`.
- Linux microphones and speakers (ADR-0049): libwebrtc gives only `index:` IDs there. `pulse.rs` reads the sound server's sink and source names through `dlopen` of `libpulse.so.0` (one connection, at most 3 s, read only, no monitor sources) for `ListDevices` and, before stage 2, for a `Join` with a `pulse:` choice. `mapping::sound_path` decides: a `pulse:` choice needs the same name in `PULSE_SOURCE` or `PULSE_SINK` (else `Protocol`) and on the server now (else `DeviceNotFound`); then the worker leaves libwebrtc's device selection alone, and its default stream goes to that name. A name in the environment without a `pulse:` choice is `Protocol`. Keep this check: the sound server quietly falls back to its default for a missing name.
- Arguments (`args.rs`): Linux takes at most one `--camera=portal|v4l2|none` (none by default). Any other argument, or any argument on another OS, sets `CHECK_FAILED`, so the worker sends `Ready` and then `Failed(Containment)`. Read the mode with `camera::mode()`.
- Camera channel (`camera_channel.rs`, Linux): descriptor 3 carries one byte and one `SCM_RIGHTS` descriptor per message. The byte names the kind: `c` for a camera, `s` for a screen; a one-byte message of any other value closes the whole channel. Each kind keeps at most four pending descriptors in arrival order; one more of a kind closes that kind's descriptors and breaks it. Each `SetCamera { on: true, remote: true }` takes the oldest with the command (`camera::Grant::take()`) and moves it into its open, or drops it if the command opens nothing; the listing path takes one for `ListDevices`. `take_handle()` is the only reader. Keep the module free of other worker modules so it builds alone.
- Linux cameras (ADR-0049): `camera/linux.rs` dispatches by `camera::mode()`: `linux_portal.rs` (PipeWire over the descriptor from the core, `node.name` IDs, shared-memory buffers only) or `v4l2.rs` (raw ioctls; IDs join driver, card and `bus_info`, all required, so a different model in the same port is `NotFound`). `linux.rs` prefixes each ID with its path (`pipewire:` or `v4l2:`), so a choice from the other path or without a prefix is `NotFound`. `yuyv.rs` holds the format policy (NV12, I420, YUYV, at most 1280x720, no MJPEG) and the YUYV conversion. A refused portal never leads to V4L2, and a chosen camera that is absent is `NotFound`. `linux_portal::connect` is the only PipeWire entry (the screen share uses it too). It calls `webrtc::InitializePipeWire()` before `pw::init`: the static libwebrtc's weak `pw_*` stubs replace libpipewire's functions in the worker and stay null until then (a null call, SIGSEGV). Keep that call.
- macOS camera (`camera/macos.rs`, AVFoundation through `objc2`): `uniqueID` IDs, NV12 at most 1280x720, no fallback camera. A `NotDetermined` permission asks the user and waits at most 60 s (`OPEN_TIMEOUT` in `camera/mod.rs` is 65 s on macOS for this). A denied or restricted permission is `Unavailable`.
- A camera error never ends the call: report `CameraState`. A chosen camera that is absent is `NotFound`; never fall back to another camera. Turning the camera off revokes frame admission, stops and joins the capture thread (at most 3 s), then unpublishes the track. A capture that does not stop in time is kept and polled; no new camera opens while it runs, and the state is `Unavailable`, not `Off`.
- Every own track (microphone and camera) needs its frame cryptor set to the current own key index. `SetOwnKey` updates all of them. The camera sends no picture before that.
- Never await a camera open in the event loop. `begin_camera` opens on its own thread, and the result comes back through a bounded channel to `camera_opened`. `CameraGate` allows one open at a time, drops a stale result and releases its camera. `SetOwnKey`, `SetKey` and `Leave` are served while an open waits.
- Remote audio follows one `Playout` (deafened and volume, ADR-0055). Apply it to every subscribed remote audio track on every connection (the own room and each open room in `others`) when it changes, when another SFU's room opens, and to each new track in `TrackSubscribed`. Set the volume before enabling a track. Deafen never changes the microphone: the core sends `SetMuted` itself, before `SetDeafened(true)`.
- The level meters (ADR-0055, ADR-0059) read `get_stats` on the 100 ms tick, on their own task (`SoundProbe`, at most one, at most 500 ms, aborted at shutdown), never in the event loop. The own track is read first, then the remote tracks all at once (`read_all`), each by one 400 ms deadline (`SOUND_READ_BUDGET`); a read that misses it is `None` and its meter keeps its level, never silence. They read the own microphone track's `media-source` level for `SoundLevel`, and the subscribed remote audio tracks' inbound level for `ParticipantLevel`, the loudest track of each identity. `mapping::LevelMeters` (one `LevelGate` each, at most `MAX_PARTICIPANTS`) sends a number when it changes, and a level above 0 again once a second (`SOUND_LEVEL_REPEAT`), so a page that attaches mid-call catches up. Silence is never repeated, except once for a participant that left.
- Remote microphone mutes (ADR-0059): send `ParticipantMuted` after each `ParticipantJoined` (`RoomChange::Joined` carries `microphone_on`), and when a remote microphone track is subscribed, muted, unmuted or unsubscribed. No microphone track counts as muted, so a participant that only listens or only shares a screen shows as muted.
- Device changes (ADR-0059): `SetDevices` goes through `switch_devices`. It never reads the system defaults in the event loop: `MediaDefaults::read` (a blocking COM query on Windows) runs once before the join, and "System default" during the call means the default when the call started. `resolve_devices` and `device_switch` check both devices before either changes, and `apply_switch` switches them and keeps `Call::sound_devices` naming the devices in use, also after a failure. A stored ID is not proof that the device works: `recording_lost` and `playout_lost` mark a device that a failed switch stopped, and the next change switches it again. A microphone switch counts only when capture runs after it. LiveKit 0.11 cannot start playout again, so a lost speaker stays lost: each later change answers `AudioDevice` and the user must rejoin. It answers `DevicesSet`. `SetDevices` also carries the camera choice, which the worker keeps for the next camera start (`camera_device`); on Linux a sound choice equal to the join's (`joined_sound`) is no sound change. A missing selected device is `DeviceNotFound` and the call keeps its devices. A "System default" that names no listed device is `Unsupported` during a call. Linux answers `Unsupported`. `select_devices` is for the join only.
- Device tests (ADR-0059): `TestDevice` is a first message, like `ListDevices`; it connects to no server. `session::test_device` opens a sound test's device first (`sound_test::open`, off the runtime threads), then applies stage 2, then runs it (`Opened::run`, on its own thread). `sound_test.rs` listens (15 s, own level) or plays a 440 Hz tone (1.5 s). Windows: WASAPI in shared mode; `E_ACCESSDENIED` is `DeviceDenied`. Linux: one PulseAudio stream through the `libpulse.so.0` handle of `pulse.rs`, the default stream with no device name and `PA_STREAM_DONT_MOVE`; a `pulse:` choice is checked with `sound_paths` as for a `Join` and reaches the stream through `PULSE_SOURCE` or `PULSE_SINK`; any other chosen ID is `DeviceNotFound`; it must open before stage 2 (new socket); `PA_ERR_ACCESS` is `DeviceDenied`. macOS: a Core Audio HAL I/O procedure (32-bit float only) on the default device or the chosen UID; the device is found before the microphone permission is checked, so a missing device never prompts; a refused permission is `DeviceDenied`. Never request a permission in a default-run test on macOS: outside an app bundle it ends the process. The camera test takes the portal remote that the core sends before `TestDevice` (`Grant::take`), opens the camera as a call does and sends pictures on tile 0 for at most 30 s. `Leave` ends any test, which ends with `Left` or `Failed`.
- Microphone settings (ADR-0062): `Join` carries `auto_level` and `mic_gain`, and `SetMicrophone` changes them in a running call. `mapping::Microphone::new` is the worker's own check (a gain over 400 percent or off the step of 5 is `Protocol`; the protocol reader refuses it first). The gain goes to the voice engine's audio processing module through `native::capture_processing::set_capture_gain_percent` (a process-wide value that every live factory applies); the automatic level goes to the published microphone track through `RtcAudioTrack::set_auto_gain_control`. Both apply at once, and `apply_microphone` applies both again after each `SetDevices`. The device tests (`sound_test.rs`) do not use them. A refusal is noted, never fatal.
- Audio notes (ADR-0058 amendment of 2026-11-25): `note_audio` in `session.rs` writes `Note` records of the target `persephone::call_worker::audio` while the log is on: the devices at the join (counts and how each was chosen, never an ID or name), the microphone settings with what the audio processing module reports, and every 5 seconds the own level, the playout state and each remote audio track's packets, samples and level (`measure_levels`). Keep them to counts, flags and levels. Never add an identity, a device ID or name, a key or a token.
- Pictures never use the control queue. `output.rs` keeps at most one waiting picture per tile (newest wins), and control messages always go out first. Pictures are RGBA in byte order R, G, B, A, at most 640x360 and 15 per second per camera tile, and at most 1280x720 and 5 per second on the screen tile (5), checked by tile index before allocation.

## Build

- The pinned libwebrtc must be verified first: `python tools/dev.py webrtc`. Set `LK_CUSTOM_WEBRTC` to the directory it prints for every cargo command. The build must never download libwebrtc.
- On Windows the prebuilt libwebrtc uses the static C runtime. Build and test this package with `RUSTFLAGS=-C target-feature=+crt-static`. `tools/dev.py` does this and builds the package apart from the rest of the workspace.
- On macOS, `build.rs` links the worker and its tests with `-ObjC`. Keep it: libwebrtc's Objective-C categories are dropped without it, and the first peer connection factory aborts. The `-ObjC` that webrtc-sys sets does not reach this package.
- `third_party/` holds vendored LiveKit crates with small marked patches (TLS 1.3 only and no proxy variables in `livekit-net`; key ring of 256 and a remote audio volume in `libwebrtc` and `webrtc-sys`; no built-in echo canceller in `webrtc-sys`, so capture never waits for playout; a microphone gain and automatic gain control in `libwebrtc` and `webrtc-sys`, ADR-0062). Read each `PERSEPHONE-PATCH.md`. They are patch sources, not workspace members.

## Checks

- `cargo test --locked -p persephone-call-worker`
- On Windows and Linux, the real-device sound test only by choice, as it records from the microphone: `cargo test --locked -p persephone-call-worker -- --ignored default_devices`
- On Linux, the contained sound tests (both stages, real sound server) after `cargo build -p persephone-call-worker`. They need the default source to be the monitor of the default sink, and a second sink: `PERSEPHONE_TEST_OTHER_SINK=pulse:<second sink> cargo test --locked -p persephone-core --lib platform::linux::call -- --ignored sound`. The test's doc comment shows a `pactl` setup.
- `cargo clippy --locked -p persephone-call-worker --all-targets -- -D warnings`
