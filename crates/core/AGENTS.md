# Key-holding core

This crate is the application entry process. ADR-0004 assigns sessions, SDK work, keys, stores, and the media broker to this process. The core runs real Matrix sessions through the SDK. The `--demo` view fixtures and demo events are synthetic; do not describe them as Matrix integration.

- Treat every UI request as hostile. Use the budgeted frame reader before body allocation, strict protocol decoding, and explicit argument validation.
- Keep bounded projections in `src/views.rs`. Preserve room, item, serialized-byte, name, body, and cursor limits. Truncate text on valid character boundaries.
- Keep identity normalization separate from message-body handling. Preserve the documented treatment of controls and bidirectional text.
- Keep room subscriptions bounded. Coalesce change notifications and fetch content through bounded calls. A slow UI must not create an unbounded event queue.
- Review lock order, wakeups, writer failure, pipe closure, and thread completion together when changing the serving loop. Do not infer full shutdown from a dropped handle or task status.
- Keep protocol violations fatal to the affected UI connection. Return bounded public error codes instead of internal diagnostics.
- Preserve UI process supervision and Windows Job ownership in `src/main.rs`, `src/ui_host.rs` and `src/platform/windows/ui.rs`. Unsupported platforms need measured equivalent controls before security claims.
- Keep per-OS code in `src/platform/<os>/` behind the traits in `vault.rs`, `credentials.rs`, `pick.rs`, `media.rs` and `ui_host.rs`. An OS without an implemented layer fails closed.
- Coordinate commands and events with `crates/core-protocol`, `src-tauri/src/core_link.rs`, the Tauri command surface, and frontend bridge.

- Screen sharing (ADR-0053): the page asks with `call_screen { on }` and names no source. `calls/screen.rs` holds the `ScreenSource` trait; `platform/linux/screen_portal.rs` shows the core's warning window and runs the ScreenCast portal (no restore token, one source), keeps the portal session open for the share and closes it on stop, on any worker end state and with the call. The remote goes to the worker with the byte `s` directly before `SetScreen`. Windows and macOS use the default `Unavailable` source; do not add a Windows chooser until the capture runs in the worker's container (`docs/evidence/screen-share-windows.md`). A cancelled or refused pick leaves the share off and never falls back to another source.
- Other SFUs (ADR-0054): `calls/other_sfu.rs` holds the pure rules (which SFU a member is on, at most 3 other SFUs, DNS host names only, the answer for each host). The core asks in its own window (`CallHost::confirm_other_sfu`, default "no") once for each host in each call, and only then requests one OpenID token and `/sfu/get` grant for that SFU with the profile's no-redirect client, and sends `Subscribe`. `View::accepts` takes a worker participant, speaker, share or video from connection `n` only when the member's membership names the SFU of `n`. A failed or ended other SFU only makes its members not reachable. Nothing is remembered after the call.
- Homeserver call tokens (ADR-0056): `calls/readiness.rs` reads the transports with its own requests (stable path, unstable path, then `.well-known`), not with the SDK's typed request. The two transports requests and the token request go through `bounded.rs`, which caps each answer while it is read and holds the only unknown-token refresh and retry rule (`room_relations.rs` uses it too); `Client::send` reads whole answers first. The `.well-known` fallback is read with `discovery::fetch`, under its ADR-0027 cap and with no token. A `wss` `url` transport gets its token from the homeserver's MSC4195 `get_token` (`calls/sfu.rs`). Its LiveKit identity is the hashed one. Keys find their member by `{user}:{device}` of the sender, and the core gives them to the worker under each backend identity of that member, again when those identities change. Such a transport is never another SFU.

- Presence (ADR-0057, proposed): `presence.rs` holds the `Writer`, which picks every sync request's `set_presence` and the `PUT` of a changed setting, at most one write a second and a carried sync value at most every 15 seconds, the bounded `Book` of contacts' presence, and `Members`, the bounded book of the members the member panel last listed (`room_settings::readers` sets it). The contacts' two and the members' four lookups a round all run at once, so a round stays within one timeout. Never let a sync request use the SDK's default `online`: pass the writer's value to `account::sync_round`.
- Devices and levels (ADR-0059, proposed): `calls/device_test.rs` holds the pure test rules; `CallController::start_device_test` runs one test at a time on its own thread, refuses it while a call runs or joins (`in_call`), stops it when a join starts and ends it after `TEST_LIMIT`. A stop recorded while the test worker starts ends the test before `TestDevice`, so no device opens; a later stop reaches the worker as `Leave`, which closes a device that opened. The test worker gets the diagnostic switch before `TestDevice` and on each change, and its records go to the log (`worker_record`, ADR-0058). A camera test's picture store is the controller's store only while no call runs. `Core::set_call_devices` also sends the microphone, speaker and camera choice to a running or joining call (`CallController::set_devices`, which sends `ToWorker::SetDevices`); the camera applies from the next camera start, and a failed microphone or speaker change is the status's `deviceChange`. Other devices' levels go to the hub as `SoundUpdate::Participants` and leave with the own level under its gap.
- Linux keyring (ADR-0061, proposed): `platform/linux/vault.rs` asks `confirm_keyring_creation` (default "no") only when `ReadAlias("default")` is `/` while a new secret is stored, at most once per open attempt, and only after a yes calls `CreateCollection` ("Login", alias `default`) and uses the collection only if the alias now names it. `store_new` owns the session-bus name `CREATION_NAME` (`CreationLock`) from its first search to its read-back, so no other core on that bus creates an item during the waits; do not move this lock to a file under a per-process directory. A core waits only `CREATION_WAIT` (5 s) for the name, on the lock's own connection with `CREATION_CALL_TIMEOUT` (1 s) per reply, then fails with `VaultError::Busy` (`keyring_busy`), because `main.rs` opens the profile before any window shows. Never add `SetAlias`. A missing bus, provider, default keyring or display is `VaultError::Missing`, which `store.rs` maps to its own `StoreState`; never fall back to another collection, the kernel keyring, a file or the passphrase alone.
- Diagnostic log (ADR-0058, proposed): `diagnostics.rs` is the only writer. It is off at every start; `main.rs` erases the old file (overwrite, sync, truncate, delete) before the profile opens. Every string passes `diagnostics/redact.rs` before the writer thread gets it. `diagnostics/events.rs` writes event metadata only; content is always `[content]`. Request records use `Call::command()`, which reads only the command tag, never arguments. Never format a secret into a record, and keep the queue, line and file limits. Turning it on goes through `confirm_diagnostics` (default "no").
